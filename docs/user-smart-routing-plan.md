# 用户智能路由组实现方案

## 目标与使用流程

用户从当前有权使用的实体分组中创建自己的路由组，并为它创建个人 API Key。外部客户端继续请求原有模型名；路由组根据策略选取支持该模型及请求协议的分组，再复用现有组内调度。成员不暴露底层渠道、凭据或上游密钥。

本次支持 price_first、stable_first、ordered、round_robin、weighted 五种策略。原有单分组 Key 保持兼容。Classic web 不增加功能；web-next 提供路由组管理和 Key 绑定。

## 数据、权限与 API

- 新增 owner 范围的用户路由组及成员，路由组与平台计费分组分离。
- 每用户最多 32 条规则，每条最多 16 个不重复的实体分组，禁止路由嵌套。
- 规则字段包含名称、启停、策略、最大尝试组数和可选的最高有效价格倍率；成员包含分组、顺序和权重。
- 新增用户路由组 CRUD，路径为 `/api/user-routes` 和 `/api/user-routes/{id}`。
- 个人 Key 创建支持 `user_route_id`，与显式 `group_id` 互斥；签发和绑定在同一事务中完成。
- 保存、Key 签发、请求规划及真正尝试前检查所有权和成员授权。授权已撤销的成员被排除，规则停用、删除或无合法成员时关闭访问，绝不退回默认组。
- 单个路由组的读取、修改和删除都限制在当前用户；跨用户标识统一按不存在处理。
- 删除/禁用不影响其他用户规则，不删除平台实体分组。

## 调度及重试语义

- 同模型、协议及能力预检后才进入可执行候选。
- ordered：按成员优先级及稳定顺序尝试。
- round_robin：跨请求轮换首选成员；失败后顺次尝试尚未尝试的成员。
- weighted：按成员权重分配首选成员，失败后无放回选取其余候选。
- price_first：使用请求上界及请求时刻的有效价格快照进行报价比较，包含分组、来源到目标组、模型覆盖及高峰倍率。
- stable_first：使用分组与模型的近期成功/失败、延迟及冷却状态选取，冷却后允许恢复尝试；请求错误不惩罚分组。
- 同一请求不重复尝试同一分组，最大尝试数量和现有组内重试边界共同限制总放大。
- 超时、上游连接或过载等明确可重试错误允许切组；用户参数错误、策略拒绝、fail-closed 模拟错误及合法安全拦截沿用既有请求终止语义。
- 流式响应提交后不跨组重放；异步任务受理后必须固定实际组，不允许重复提交任务。
- 保留认证用户、Key、来源组和请求关联；实际目标组必须进入计费和观测上下文。

## 计费与资源生命周期

每个分组尝试独立固定价格快照和预留。失败且尚未交付的尝试必须确认撤销预留后才尝试下一组；清理失败则停止请求，避免暂存预扣和重复收费。成功请求按实际执行组及其固定价格结算，流式生命周期继续由现有交付结束钩子负责。

不能将多个不同价位分组的渠道扁平化后沿用首组选价；不能先调用上游再检查余额。Key 总额、用户额度及原有平台限制在跨组尝试中继续生效。

## 前端

新增用户路由组列表、创建与编辑、启停和删除操作。成员选择来自现有用户可选组目录，支持顺序、权重及倍率上限编辑；稳定行标识用于成员编辑。

Key 创建表单增加单分组/智能路由组选择，正确处理规则停用、不可用和创建失败；保留现有密钥只展示一次的流程。界面文案说明策略和备用切换行为，不展示实现细节。

## 回归与交付

不在本机安装依赖、构建、测试或运行格式化器。静态审查与 `git diff --check` 后，通过令牌 API 与 Git 提交远程 CI。

覆盖：迁移兼容、所有者隔离、越权/撤权、停用/删除规则 Key 关闭访问、五策略排序、价格上限、A 组失败到 B 组成功的真实计费、失败预留释放、不可重试错误停止、流式交付后禁止重放、前端表单与 Key 绑定。

OpenAPI 与生成客户端在远程生成后回收产物更新；运行 Rust、前端、数据库和发布相关门禁。使用独立功能分支，不直接修改或合并主开发分支；PR 文案只写问题、方案与影响范围，不包含验证、CI 或操作过程。
