# 插件安装与运维

本文面向管理员。开发插件看[插件开发](plugin-development.md)，字段和协议看[插件协议参考](plugin-protocol-reference.md)。

## 1. 安装前检查

确认以下条件：

- 每个节点的操作系统、CPU 架构和解释器满足插件清单要求；
- 服务账号可以读写并执行插件缓存目录；默认目录是运行目录下的 `data/plugins`；
- 插件来源可信。未签名插件可以安装，但签名只表示发布者身份，不代表代码经过安全审核。

当前支持的固定入口包括模型资料目录、商户服务检查、渠道监控检查、渠道模型映射检查、外部账户余额分析、渠道健康事件和商户服务事件。插件还可以在插件管理、渠道监控、模型映射、商户服务和外部账户页面显示固定格式的静态内容。

插件不能注册任意 API、URL、计划任务或页面代码，也不能修改钱包、价格、权限、数据库或实时路由。实时外部余额读取必须由用户每次单独同意。监控目标启停必须由管理员确认，详见[插件动作确认](plugin-actions.md)。

## 2. 上传并启用

1. 使用管理员账号进入“插件管理”。
2. 上传 `.afplugin` 或符合格式的 `.zip` 文件。
3. 如果插件需要公开配置，展开“可选配置”并填写 JSON；不需要时使用 `{}`。
4. 点击“安装并启用”。
5. 查看“节点运行状态”，确认节点显示“就绪”。

常规上传不需要填写摘要、公钥或签名。安装器会检查包格式、配置、启动握手和健康状态。普通上传会登记制品；手工登记的制品需要先审批。

配置会发送给插件，只能填写公开参数，例如语言或显示数量。不要填写密码、访问令牌、Cookie 或其他凭据。

限制：压缩包最多 128 MiB，展开后最多 512 MiB，最多 100,000 个条目。链接、特殊文件、重复路径、大小写冲突和越界路径会被拒绝。

插件安装包保存在数据库归档中，节点会自动下载并校验，不需要手工复制插件目录，也不需要额外的对象存储。

## 3. 升级、停用、回滚和卸载

| 操作 | 作用 |
| --- | --- |
| 升级 | 上传相同 ID 的新版本并启用；旧版本和部署记录保留。 |
| 停用 | 暂停调用；包、配置和历史记录保留。 |
| 回滚 | 选择可用的历史部署恢复；恢复会生成新的部署代次。 |
| 卸载 | 停止部署并通知各节点清理缓存；数据库归档和审计记录保留。 |
| 撤销制品 | 禁止某个包继续使用，并停用引用它的部署。 |
| 清理制品 | 释放已撤销且没有启用引用的归档和缓存；元数据和审计保留。 |

修改代码、清单或资源后，递增 `pluginVersion` 并发布新包，不要覆盖已经登记的制品。操作遇到代次冲突时，刷新页面后重试。

卸载、清理和节点恢复都可能等待离线节点下次上线。一个节点启动失败时，先查看该节点的错误码和依赖，不要重复上传同一个包。

## 4. 多节点部署

生产环境使用共享 PostgreSQL 或 MySQL 和共享 Redis。所有节点应运行兼容的 AnyFlows 版本，并具备插件所需的系统依赖。当前不会按节点架构自动选择不同插件包，因此同一部署的节点必须兼容。

服务启动时恢复部署，之后每 30 秒协调一次。缺少或损坏的缓存会从共享归档恢复。旧版手工登记制品可能没有共享归档；要自动分发，请重新上传安装包。

节点状态含义：

| 状态 | 含义 |
| --- | --- |
| 已启用 | 管理员要求运行，不代表节点已经启动。 |
| 待就绪、下载中、启动中 | 节点正在恢复或启动。 |
| 就绪 | 节点租约有效，代次、摘要和运行状态一致。 |
| 失败 | 启动或运行失败，查看固定错误码。 |
| 过期 | 节点或插件观察超过 120 秒未更新，不计入就绪数量。 |

## 5. 隔离策略

服务配置：

```toml
[server]
plugin_isolation = "auto"
```

| 策略 | 说明 |
| --- | --- |
| `auto` | 默认策略。Linux 有 `setpriv`、`prlimit` 时启用资源限制；缺少工具时使用普通进程。Windows 使用 Job Object 清理进程树。 |
| `trusted` | 按服务账号运行，不附加资源限制，只适合明确受信任的插件。 |
| `restricted` | Linux 强制资源限制：地址空间最多 4 GiB，累计 CPU 时间最多 300 秒。 |
| `require_sandbox` | Linux 使用 Bubblewrap 和命名空间隔离，插件不能直接访问外网。 |

`restricted` 和 `require_sandbox` 在不支持的平台或缺少工具时启动失败，不会自动降级。Windows Job Object 只负责清理进程树，不提供文件系统或网络沙箱。

## 6. 签名和官方标识

自有插件可以不签名。需要显示发布者或官方来源时，在服务配置中登记 Ed25519 公钥：

```toml
[[server.plugin_trusted_signers]]
key_id = "publisher-example"
public_key_base64 = "<Base64 编码的 32 字节公钥>"

[[server.plugin_official_signers]]
key_id = "official-publisher"
public_key_base64 = "<官方发布者提供的 Base64 公钥>"
```

签名验证只改变显示的验证状态，不授予能力，也不改变隔离策略。命中已配置公钥但签名无效时，安装会失败。

## 7. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 包被拒绝 | 检查 ZIP 格式、入口路径、大小、重复路径和越界路径。 |
| 需要授权能力 | 在部署的“高级管理”中授予清单要求的精确 capability。 |
| `startup_failed` | 检查入口程序、解释器、架构、动态库和服务账号权限。 |
| 一个节点失败，其他节点正常 | 对比节点系统依赖、架构、隔离工具、公钥和缓存目录权限。 |
| 已启用但页面没有数据 | 检查插件是否就绪、能力是否授权、用户是否有对应业务权限。 |
| 操作返回代次冲突 | 刷新部署状态后重试，避免多个管理员同时修改。 |
| 开启强隔离后无法启动 | 检查 Bubblewrap、命名空间和内核能力；强隔离不会自动降级。 |
| `artifact_missing` 或 `archive_invalid` | 检查共享归档、数据库记录和节点缓存；旧手工制品可能没有共享归档。 |

管理接口路径和参数见[插件协议参考](plugin-protocol-reference.md#7-管理接口)。
