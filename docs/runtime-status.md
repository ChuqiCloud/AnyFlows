# 运行状态

管理员可从控制台侧栏打开「运行状态」，查看服务节点、依赖连接和近期缓存用量。监控页面及接口仅向管理员开放。

## 监控项目

- **服务节点**：节点名称、版本、启动时间、在线状态，以及进程 CPU 和内存趋势。点击节点卡片查看详情，每页展示 6 个节点。
- **数据库**：当前进程实际连接的 SQLite、PostgreSQL 或 MySQL，以及连接探测状态和耗时。
- **Redis**：是否配置、能否读写节点注册信息，以及操作耗时。不会返回连接地址、用户名或密码。
- **AI 上下文缓存**：最近 24 小时的输入令牌、缓存读取和写入令牌、有缓存用量的请求数，以及上游确认与估算用量的请求数。

CPU 按进程使用的核数显示，例如 `0.5 核`。内存区分进程常驻内存、主机已用内存和容器内存限制。完整资源采集适用于 Linux；其他平台或无法读取的资源显示为 `—`。

## 多节点部署

连接同一 Redis 逻辑数据库的节点会汇总到同一页面。节点名称来自 `HOSTNAME` 或 `COMPUTERNAME`，缺少时生成临时名称；每次进程启动分配独立实例标识。不同部署环境应使用不同 Redis 逻辑库或实例。

节点每 10 秒更新心跳。超过 30 秒未更新时标记为数据过期，超过 5 分钟从注册表移除。Redis 连接失败时保留最近观测数据，并将节点状态标记为未知。注册表最多保留 256 个实例，达到上限时页面显示提示。

未配置 Redis 时，页面仅显示当前请求命中的节点，负载均衡后的结果可能变化。多节点部署应使用共享 Redis。

## 采样与统计口径

资源每 10 秒采样，最近 60 个采样点保存在进程内存中，重启后清空。页面隐藏时暂停刷新。长期历史和告警需使用独立监控系统。

数据库和 Redis 状态由后台探测，页面读取最近结果。缓存用量每分钟更新一次，统计最近 24 小时，查询限时 2 秒。多节点通过 Redis 协调查询，未配置 Redis 时由当前节点查询。失败或过期时保留旧值，并显示异常状态和采样时间。

缓存令牌仅汇总公共调用账本中上游确认的用量，输入令牌统一为包含缓存的总量，估算用量单独计数。提供商可能不返回缓存字段，因此页面不计算缓存命中率。

统计不包含 Redis 存储占用、提供商内部 KV 缓存容量，以及企业扩展独立维护的服务账号用量账本。
