# 版本检测与手动升级

管理员可在「系统设置 → 站点设置 → 版本与更新」查看当前节点版本、构建信息、部署平台与匹配的发布包。检测直接读取 GitHub Releases，不经过第三方更新源。稳定版本只选择稳定发行，预发行版本可检测 alpha、beta、rc 和稳定发行；按 SemVer 比较版本，检查结果缓存一分钟。GitHub 限流或网络故障时可稍后重试。

## 二进制部署

默认二进制发行包同时提供 `anyflows` 主程序和 `anyflows-launcher` 启动器，由启动器托管主程序并默认启用在线更新。启动器等待主程序退出后安装已校验的新版本，再自动拉起主程序；停止服务时会先通知主程序优雅退出。默认启动器不会替换或自动升级自己。

启动器继承服务管理器或宝塔等面板注入的环境变量，并将其传给主程序。主程序工作目录下的 `.env` 可提供缺省值；同名的父进程环境变量优先。也可用 `--env-file PATH` 指定文件，文件语法遵循 dotenv 格式。缺省 `.env` 不存在时继续启动；指定文件不可读或格式错误时会安全报错，不输出文件内容。启动器默认继承标准输出和错误输出，便于服务管理器收集日志。

默认在解压目录执行 `./start.sh`，Windows 执行 `start.cmd`。托管面板的启动命令设为 `anyflows-launcher`，工作目录设为配置和数据所在目录；主程序参数放在 `--` 后，例如 `anyflows-launcher --env-file /etc/anyflows/anyflows.env -- SERVER_ARGS...`。显式文件相对路径以启动器启动目录解析，缺省 `.env` 以主程序工作目录解析。环境文件在启动器启动时加载，修改后重启启动器生效。主程序标准输入用于私有控制与存活通知，不透传面板标准输入；标准输出和错误输出沿用面板管道。

安装更新前请自行备份数据库、配置和计费 WAL；安装期间当前节点会短暂不可用。裸启动仍受支持，直接运行 `anyflows` 时继续使用现有的程序替换流程，安装后由管理员手动重启：

```sh
anyflows update check
anyflows update install v0.3.0-beta.4 --yes
```

将示例标签替换为检测到的版本；不支持降级、跳过校验或指定任意下载地址。命令自动识别编译目标，下载对应原始二进制和同名 `.sha256`，核对文件名、大小与 SHA-256 后替换程序。程序目录保留 `anyflows-backup-*` 旧二进制，配置、数据库和 WAL 不会被覆盖。裸启动安装完成后由管理员启动或重启服务。升级前应核对目标版本对操作系统和数据库的要求。

默认 systemd 部署使用启动器，服务账号仅能写入数据目录，程序目录保持只读。通过服务单元的 `EnvironmentFile` 或面板设置注入的环境变量会传入主程序；缺省 `.env` 位于服务工作目录 `/var/lib/anyflows`。自定义启动器参数时，可使用 `--env-file PATH` 指定环境文件。裸启动部署可使用完整程序路径执行更新命令，并由管理员停止、启动服务；无需放宽默认服务单元的文件系统保护。

二进制部署默认开启网页「下载并安装」，可设置 `ANYFLOWS_ENABLE_BINARY_UPDATE=false` 关闭。裸启动时程序目录须可写；管理员确认备份后手动触发安装。裸启动的网页安装不自动重启进程，安装后显示待重启状态，重启前不会再次安装。请通过原有服务管理器重启并检查 `/readyz`。权限不足、校验失败、版本变化或有其他安装进行时会拒绝更新。

Windows 使用 `anyflows.exe` 执行对应命令；若系统锁定程序文件，停止服务后使用已校验的完整发行包替换程序。旧程序回退只恢复二进制，不会自动降级数据库；若新版本已经迁移数据库，按对应版本的迁移说明处理备份恢复。

## 容器与多节点

Docker 仅提供版本检测和发布说明；后端和命令行同时禁止替换程序，即使开启网页安装配置也不例外。升级时更新镜像标签并重新部署容器。

所有操作只作用于接收请求的当前节点。多节点环境应通过固定节点入口逐台升级，先摘除流量、等待请求排空和计费持久化，再更新、启动与检查就绪状态。负载均衡入口不能作为集群统一升级入口。

## 发布包

公开 tag 发布为 Linux glibc、Windows MSVC、macOS 分别构建 amd64 和 arm64 原生包，包含 Classic、Next 内置前端；Windows 使用 ZIP，其他平台使用 tar.gz，同时发布原始二进制及各自 SHA-256 文件。Linux glibc 构建运行环境为 Ubuntu 24.04，需要 glibc 2.39 或更新版本及 OpenSSL 3 运行库。macOS 包要求 macOS 15 或更新版本，并静态链接 OpenSSL；Windows 包静态链接 OpenSSL 与 MSVC C 运行库。

自动识别区分操作系统、CPU 架构及 Linux libc，不会给 musl 构建选择 glibc 文件。未发布对应平台包时明确显示无匹配包，保留手动部署方式。
