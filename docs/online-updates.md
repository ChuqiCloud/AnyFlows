# 版本检测与手动升级

管理员可在「系统设置 → 站点设置 → 版本与更新」查看当前节点版本、构建信息、部署平台与匹配的发布包。检测直接读取 GitHub Releases，不经过第三方更新源。稳定版本只选择稳定发行，预发行版本可检测 alpha、beta、rc 和稳定发行；按 SemVer 比较版本，检查结果缓存一分钟。GitHub 限流或网络故障时可稍后重试。

## 二进制部署

默认只允许检查和下载安装包。推荐先备份数据库、配置和计费 WAL，再停止当前节点，在原程序位置以具备程序目录写权限的管理员身份执行：

```sh
anyflows update check
anyflows update install v0.3.0-beta.4 --yes
```

将示例标签替换为检测到的版本；不支持降级、跳过校验或指定任意下载地址。命令自动识别编译目标，下载对应原始二进制和同名 `.sha256`，核对文件名、大小与 SHA-256 后替换程序。程序目录保留 `anyflows-backup-*` 旧二进制，配置、数据库和 WAL 不会被覆盖。安装完成后由管理员启动或重启服务。升级前应核对目标版本对操作系统和数据库的要求。

默认 systemd 部署保持 `ProtectSystem=strict`，服务账号没有程序目录写权限。使用完整程序路径操作，例如 `/usr/local/libexec/anyflows/anyflows update install <标签> --yes`，前后分别执行 `sudo systemctl stop anyflows` 和 `sudo systemctl start anyflows`。不要通过放宽服务单元的文件系统保护来启用网页安装。

自主管理、明确允许程序自行替换的二进制部署，可设置 `ANYFLOWS_ENABLE_BINARY_UPDATE=true` 开放网页「下载并安装」。程序目录须可写；管理员确认备份后手动触发安装。网页不自动重启进程，安装后显示待重启状态，重启前不会再次安装。请通过原有服务管理器重启并检查 `/readyz`。权限不足、校验失败、版本变化或有其他安装进行时会拒绝更新。

Windows 使用 `anyflows.exe` 执行对应命令；若系统锁定程序文件，停止服务后使用已校验的完整发行包替换程序。旧程序回退只恢复二进制，不会自动降级数据库；若新版本已经迁移数据库，按对应版本的迁移说明处理备份恢复。

## 容器与多节点

Docker 仅提供版本检测和发布说明；后端和命令行同时禁止替换程序，即使开启网页安装配置也不例外。升级时更新镜像标签并重新部署容器。

所有操作只作用于接收请求的当前节点。多节点环境应通过固定节点入口逐台升级，先摘除流量、等待请求排空和计费持久化，再更新、启动与检查就绪状态。负载均衡入口不能作为集群统一升级入口。

## 发布包

公开 tag 发布为 Linux glibc、Windows MSVC、macOS 分别构建 amd64 和 arm64 原生包，包含 Classic、Next 内置前端；Windows 使用 ZIP，其他平台使用 tar.gz，同时发布原始二进制及各自 SHA-256 文件。Linux glibc 构建运行环境为 Ubuntu 24.04，需要 glibc 2.39 或更新版本。macOS 与 Windows 需要满足对应构建运行环境的系统要求。

自动识别区分操作系统、CPU 架构及 Linux libc，不会给 musl 构建选择 glibc 文件。未发布对应平台包时明确显示无匹配包，保留手动部署方式。
