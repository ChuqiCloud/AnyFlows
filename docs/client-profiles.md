# 客户端档案

客户端档案用于配置上游请求的客户端身份和会话策略。管理员可从控制台侧栏进入「客户端档案」。

## 创建和修改

复制内置的标准请求、Claude Code、Codex 或 OpenCode 档案，填写唯一标识和显示名称，再配置适用协议、凭据类型、身份请求头和会话策略。标识支持小写字母、数字、下划线和连字符，最长 64 个字符。内置档案仅供复制，不能直接修改。

身份请求头仅支持页面列出的字段，不接受 API Key、Cookie 或认证请求头。服务地址、认证和正文转换由适配器管理。切换服务后需检查保留的身份字段是否适用。图标标识可填写 `OpenCode`、`OpenAI` 或 `Anthropic` 等已支持的品牌名，未识别的标识显示通用图标。

点击「校验配置」后创建档案或发布修订。该操作仅检查配置格式，实际可用性需通过渠道探测和 API 调用确认。档案列表支持按名称、标识搜索，以及按服务、状态筛选。

## 给渠道选择修订

在渠道列表点击指纹图标，打开「客户端档案配置」。选择兼容档案，再从修订历史选择要使用的版本，确认后点击「切换到此修订」。渠道配置与档案编辑分别保存。

渠道绑定指定的档案修订，发布新修订后需手动切换，回滚时可重新选择旧修订。保存时会检查凭据兼容性和请求头冲突。旧版 Claude 身份配置发生冲突时，先关闭旧配置并保存渠道，再切换档案。

档案详情显示修订历史和渠道引用。停用档案后，绑定渠道在配置更新生效后拒绝新请求，已开始的请求继续执行。多节点部署存在配置传播延迟。

## 会话策略

默认使用客户端提供的会话标识。自定义档案可选择「明确标识优先，首条消息尽力关联」：缺少会话标识时，根据首条用户消息生成隔离摘要。相同主体使用相同开场可能关联到同一会话，建议客户端提供稳定的会话标识。

会话关联不提供跨账号访问权限。上游私有响应状态的续接能力见 [对话兼容](conversation-compatibility.md)。

## OpenCode 渠道

创建渠道时选择 OpenCode，并按模型原生协议选择 Chat、Responses 或 Messages。服务地址由系统内置，不需要填写 Base URL。

在凭据抽屉选择 API Key 或「公开访问」。公开访问不填写密钥，渠道只允许一条公开凭据，不能与 API Key 混用；如需两种方式，请分别创建渠道。公开凭据参与并发、健康及调用统计。选择客户端档案时使用兼容的「OpenCode（公开访问）」或自定义档案；现有 OpenCode 档案的冻结修订继续仅适用于 API Key。

公开访问的可用模型由上游决定，目录查询成功后仍需验证实际推理。模型名称包含 `free` 不会自动将平台价格设为免费。公开渠道调用失败会直接返回错误，不会自动切换到其他渠道或收费 Key。

渠道的「客户端档案配置」支持切换 Inference v1 和 Zen v1 入口。入口独立保存，切换后应重新发现模型并验证调用。

模型要求完整的客户端工具声明时，可在「客户端档案配置」中开启「完整工具兼容」，默认关闭。该选项补充内置工具声明，保留已有同名工具的参数和语义；网关不执行这些工具。

模型仅调用不可用的内置工具，且未返回有效内容时，系统会说明工具不可用并请求续答，最多一次。已返回内容、混合调用真实工具或再次调用不可用工具时，请求失败。两轮共用凭据、会话、输出上限和总超时，按一次请求结算。

上游使用 SSE 时，下游仍可选择流式或完整 JSON。Chat、Responses 和 Gemini 保留可表达的推理文本。转为 Messages 时，服务端会协商不输出无签名思考，推理用量仍计入统计；明确要求无法转换的思考输出时会拒绝请求。

## 检查上游请求头

在「调试追踪」中开启请求头采集后，发起模型调用。打开对应记录，依次选择「查看 Header」→「上游请求记录」→候选→「请求头」，查看档案和适配器处理后的请求。调用方传入的请求位于「下游请求」。

OpenCode 请求可检查 `x-opencode-client`；启用会话关联时，还会生成 `x-opencode-session`、`x-opencode-session-id` 和 `x-opencode-project` 等服务字段。档案中的 `User-Agent` 会实际发送，但日志中的值固定脱敏，认证字段也不会显示明文。修改采集设置只影响后续请求，未采集的历史记录无法补回。

OpenCode 免费模型可能限制服务器出口 IP。请求头符合配置但调用失败时，应结合上游状态码和错误正文排查。
