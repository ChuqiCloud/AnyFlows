# 插件能力扩展设计

本文定义 AnyFlows 上传式插件扩展到业务查询、平台连接器、受控操作、事件任务和声明式界面的边界与实施顺序。它是宿主开发设计，不表示下文提到的能力已经能由 `.afplugin` 使用。当前可安装插件实际支持范围见[插件开发指南](plugin-development.md#先看支持范围)。

## 目标

让插件能扩展更多业务模块，同时保持插件不能自行取得登录会话、数据库、上游密钥、路由或账务写权限。模块接入仍由宿主负责：宿主认证调用者、选定插件和固定能力、构造最小输入、检查输出，并执行任何需要写入的操作。

扩展面分为五类：

| 扩展面 | 插件负责 | 宿主负责 | 目标首批能力 |
| --- | --- | --- | --- |
| 业务查询 | 检查、计算、归纳和建议 | 身份、数据授权、查询投影、结果展示 | 模型、渠道、路由、任务、计费说明、运行状态 |
| 外部连接器 | 按固定契约解释外部平台响应 | 认证、密钥保管、出网、SSRF、防重放、余额快照 | 外部账户资料、余额读取、模型目录和只读健康检查 |
| 受控操作 | 固定动作 active-channel-monitor.target.set-enabled@1：插件只提供 enabled 布尔建议；宿主持久化 5 分钟提案，管理员二次确认后按监控配置版本执行并记录结果 | 更多动作 ID、其他业务对象和外部副作用仍未接入 |
| 事件和任务 | 对固定事件投影进行有界处理 | 事件筛选、持久队列、租约、重试、审计、通知 | 渠道状态变化、商户服务状态变化、审核结果通知 |
| 声明式界面 | 提供菜单文案、表单和结果描述 | 路由、权限、组件、翻译加载和 API | 插件设置表单、检查结果卡片、宿主页面入口 |

这五类不共享一个“万能执行权限”。每类都有自己的宿主端口、数据投影和权限范围，插件只声明它需要的固定能力。

## 共同执行模型

所有上传插件继续使用版本化、平台中立的 JSON Lines Sidecar 契约。通用能力的调用由一个宿主入口主动发起；插件不轮询宿主、不自选调用者、不注册 URL，也不能从 capability 名推导权限。

每个请求至少绑定以下信息：

- 插件 ID、包摘要、部署代次、能力 ID 和版本；
- 宿主生成的 request ID、截止时间、输入/输出字节上限；
- 宿主侧保留的认证主体、角色、资源归属结论和部署能力授权；这些上下文不默认传给插件。Sidecar 仅接收完成此项处理所必需的最小输入，优先使用宿主生成的匿名/短期引用，而非稳定用户 ID、邮箱或原始角色资料；
- 该能力允许使用的最小 JSON 输入，以及宿主独立验证的输出 Schema。

宿主必须拒绝未声明、未协商、未授权或版本不匹配的能力。结果返回前复核部署代次、撤销状态和执行期间需要保持有效的权限。Sidecar 不获得数据库连接、任意 HTTP 客户端、浏览器代码执行、运行时 Rust ABI 或通用命令执行。

新增 capability 必须使用新的稳定 ID 或版本，不允许通过扩大旧 Schema 的字段含义来授予权限。manifest 中的声明只是兼容性说明；它不能取代宿主的固定调用入口和管理员授权。

## 业务查询与建议

查询入口沿用当前只读评审模式：宿主确认调用人有权查看目标资源，把资源投影为最小 JSON，再调用明确授予该能力的插件。插件的输出只能作为数据或建议展示，不会自动写入业务状态。

可继续接入的对象包括：模型与价格说明、渠道配置摘要、路由候选与规则解释、任务状态与公开结果元数据、商户供给状态、运行状况和用量报告。每个对象须分别定义：

1. 可运行的角色和资源归属规则；
2. 输入字段、敏感级别、最大项数和字节上限；
3. 输出类型、文本长度、错误状态和是否允许分页；
4. 数据版本或事件快照及返回前的新鲜度复核方式。

不要把完整数据库行、请求日志、渠道 URL、模型 Key、Cookie、用户身份凭据、财务明细或隐私字段作为“上下文”一次性传给插件。对于需要较多数据的查询，宿主按模块分批构造有上限的投影。

## 外部平台连接器

外部连接器必须走宿主管理的类型化连接器端口，不把外部密钥放进普通 `publicConfig`、通用能力输入或 Sidecar 标准输出。默认情况下，Sidecar 永远不接收原始凭据，也不接收可自行兑换凭据的 bearer token。插件只能看到宿主签发的 opaque handle 和本次请求上下文，并通过受限的 host-managed HTTP proxy 请求外部平台；宿主负责凭据加密存储、主体绑定、出网客户端、目标地址/方法/路径 allowlist、凭据注入、超时、响应体上限、重定向检查和脱敏日志。proxy 返回给插件的响应仍须限制字段和大小，不能把原始登录响应、Cookie 或无关个人资料直接透传。

如果某个外部协议必须由插件代码持有或变换明文凭据，不能把“短期有效”视为安全隔离。该连接器须走单独的高信任模式：安装界面明确警告凭据可被插件代码读取；管理员逐 connector 批准用途与账户范围；配置最短 TTL、可撤销 scope、独立审计和泄漏响应步骤，并要求适用的平台隔离策略。普通 Sidecar 能力不得隐式升级到该模式。

接口分为独立能力：

| 能力 | 目标语义 | 明确不包含 |
| --- | --- | --- |
| 外部身份验证 | 通过宿主代理检查用户提交的外部凭据并返回稳定外部主体 | AnyFlows 登录会话、密码复用、自动授予本地角色 |
| 外部账户资料读取 | 通过宿主管理的凭据读取账户标识和公开资料 | 将资料同步后自动覆盖 AnyFlows 用户资料 |
| 外部余额快照读取 | 按时点记录币种、金额、外部版本或观察时间 | 把外部余额记为 AnyFlows 可消费余额 |
| 外部目录/健康读取 | 获取经固定目标策略验证的模型或健康状态 | 上游模型自动入库、定价或路由自动变更 |

宿主须保存外部账户和余额的来源、观察时间及关联主体。余额快照是对账数据，不是本地钱包资产；余额变化不能触发本地扣款、充值或跨平台冲账。账户解绑、凭据替换、撤销和重新授权都须有明确流程及审计。

当前已存在 NewAPI/Sub2API 内置连接器和 `PlatformConnector` 类型化端口；这不等同于任意 `.afplugin` 已能接管外部登录或余额读取。Sidecar 连接器适配需要单独定义凭据帧、外部认证确认、主体绑定和撤销契约后才可开放。

## 受控操作

插件先返回**操作提案**，宿主不把提案当命令执行。每个可执行操作使用固定 action ID、版本化输入 Schema、明确目标资源和权限 scope。宿主必须重新加载目标资源、验证当前角色、重新计算允许的字段，并记录提案摘要、调用者、确认人和最终结果。

操作流程分成两类：

1. **本地事务操作**：由宿主服务在一个事务中校验并提交业务变更，同时写入审计和幂等记录。插件不能提交 SQL、传入账户 ID 绕过归属验证或自行制定价格。
2. **外部副作用操作**：由宿主创建 durable outbox 命令，再由受控 worker 通过 host-managed HTTP proxy 发送。插件最多提出经过 Schema 校验的请求建议，不能自行宣布操作已完成或写入结果状态。必须预先定义幂等键、结果查询方式、未知结果处理、重试策略和对账状态；宿主根据代理观察到的响应、外部结果查询和 reconciliation 更新状态。网络超时不能直接视为失败后重放。

第一批只考虑可撤销、非资金、容易审计的操作，例如生成配置草稿、在用户确认后提交白名单字段的配置变更，或请求宿主重新检查某个资源。删除、发布、凭据轮换等破坏性动作应有二次确认。充值、扣款、提现、结算、倍率、钱包和余额调整不属于通用插件写能力；任何资金流程必须继续由账务服务拥有，并独立完成授权和对账设计。

异步或资金相关任务在真正执行时重新校验发起人的权限。权限已撤销、目标版本变化、部署代次变化或操作提案过期时，任务必须安全取消或进入人工核对，不能继续使用旧授权执行。若资金预留已经存在，只能由宿主账务事务释放或冲正；插件不得释放、确认或重新分配余额。

## 事件与后台任务

事件订阅采用宿主维护的封闭事件目录，不支持 `*`、任意表变更订阅或插件自行提供 SQL filter。每个事件类型都有字段白名单、资源归属、可订阅角色、最大投影尺寸和 retention 规则。

投递采用持久化队列及至少一次语义。每次处理输入都包含稳定的 `eventKey`，重试时保持不变，插件可用它作为副作用的幂等键。消费记录绑定插件 ID、制品摘要、部署代次和订阅版本。worker 通过租约 claim，带租约恢复、指数退避、最大重试、死信和管理员重放。调用前后复核部署是否仍启用、事件是否仍在保留期和权限是否仍有效。事件结果 API 不返回 `eventKey` 或原始输入。

首批任务是对已有安全事件投影做异步分析并生成报告或通知草稿。插件不得直接发邮件、写用户通知表、执行付款或启动自身调度器。需要用户可见通知时，由宿主根据固定通知类型和经过校验的文本代为创建。

后台 worker 的持久化记录、重试和结果状态属于宿主数据库。Sidecar 只处理单次有期限的输入，不持有任务锁，也不负责调度、重试或生命周期恢复。

## 声明式界面

上传包不能携带 HTML、JavaScript、React 组件、CSS、远程页面地址或可动态导入代码。新的插件界面使用经过 Schema 校验的 JSON 声明，由 AnyFlows 前端内置的安全组件渲染。

允许逐步提供的贡献点：

- 在固定模块槽位显示命名空间化入口或结果卡片；
- 使用有限字段类型和校验规则生成配置表单；
- 使用声明式列、标签、状态和分页展示宿主返回的数据；
- 绑定已经注册的宿主 capability action，而不是任意 URL。

贡献声明必须包含稳定插件 ID、显示资源 key、可见角色、所需宿主 capability 和版本。前端按角色及运行时 capability 决定是否显示；后端仍对每次 API 请求重新鉴权，隐藏菜单不是权限检查。

需要自由页面逻辑的功能继续使用源码编译的 `ConsoleExtension` 并随前端发布，不能从上传插件动态加载代码。用户登录、认证凭据、密码、支付确认和资金页面不能由插件替换。

## 身份、信任和隔离

- 包签名保持可选，用于来源识别；签名不能授予 capability。
- 安装、审批和执行权限分别管理。用户安装插件不会自动得到管理员能力。
- 插件授权按插件、能力 ID、版本、部署代次和环境绑定；管理员可随时撤销。
- 节点只运行共享数据库中当前启用且 digest、generation、租约一致的部署。
- 操作日志记录插件身份、调用入口、能力版本、request/event ID 和结果分类；不记录凭据或原始敏感 payload。
- OS 进程隔离只能降低影响范围，不能代替宿主授权、最小数据投影和输出验证。

插件由管理员安装即表示信任该段业务代码。用户自带插件、Marketplace 插件和官方来源必须明确区分；“官方”识别不能覆盖代码审查和当前部署授权。

## 交付顺序

扩展按可独立验证的版本交付，每阶段都需要实际宿主入口、示例、文档和远程流水线覆盖：

1. **业务只读目录**：补齐运维、路由、任务、用量等安全投影和可执行示例。
2. **连接器能力**：为账户资料、余额快照和外部目录定义专用凭据/出网契约，把第三方实现接入类型化连接器端口；验证加密、主体绑定、撤销、SSRF 和 snapshot provenance。
3. **受控操作**：先实现配置草稿和非资金幂等操作；覆盖确认、权限复核、版本冲突、审计和失败恢复。
4. **事件与任务**：新增独立事件 outbox、消费租约和死信流程；从只读分析投递开始。
5. **声明式界面**：先开放固定槽位、设置表单和结果卡片；复杂交互仍使用源码编译扩展。
6. **更高风险操作**：每类业务单独评审和设计；资金及身份权限不因通用插件扩展而开放。

不得仅为减少项目数把这些步骤塞进一个无边界通用执行器。每阶段都保持安装简单：上传包、查看所需能力、由管理员一次授予明确范围、等待节点就绪。

## 新入口合入条件

每项新增能力都必须同时具备：

1. 固定、带版本的 capability/action/event ID，以及精确输入和输出 Schema；
2. 后端主体认证、角色检查和资源归属验证；UI 隐藏不能充当授权；
3. 明确的数据字段清单、敏感级别、数据保留和最小化投影；
4. 部署授权、代次绑定、撤销行为、节点就绪和执行中权限复核；
5. 超时、并发、字节上限、分页、输出文本和运行资源上限；
6. 对外部副作用规定幂等、未知结果、结果查询、重试、对账和审计；
7. 针对撤销、部署升级、权限变化、竞态和节点离线的回归覆盖；
8. 可运行的示例插件、准确的用户文档和运维故障说明。

如果某能力无法定义其中任何一项，就不能仅凭插件作者声明而开放执行。

## 当前支持状态

本设计文档定义的是目标接口和分期，不是现有运行能力的承诺。当前底层已有几个原型，但尚未接成完整产品流程：

| 原型 | 已有 | 尚未完成 |
| --- | --- | --- |
| 插件管理界面 | 从公开 `configSchema` 使用宿主内置控件渲染受限字段；Manifest 可声明最多 16 个静态 `plugin_management` 信息卡，宿主只渲染纯文本 | 业务模块菜单、动态结果卡片、插件贡献的操作按钮 |
| 受控操作 | 固定动作 active-channel-monitor.target.set-enabled@1：插件只提供 enabled 布尔建议；宿主持久化 5 分钟提案，管理员二次确认后按监控配置版本执行并记录结果 | 更多 action ID、其他业务对象与外部副作用仍未接入 |
| 外部只读代理 | `PluginProxyRequest/Response` 语言中立 DTO 和 JSON Schema/OpenAPI 定义；请求不含 URL、凭据、header 或 body，限制在 host endpoint ID 与 GET/HEAD 查询参数 | Sidecar 双向 callback 帧、运行时 endpoint 注册、凭据注入、host HTTP 代理和外部账户连接器接线 |
| 持久事件投递 | 独立事件表、封闭类型投影、同事务渠道健康与商户公开状态生产者、受监督 worker、部署/授权/制品复核、Sidecar 调用、lease、退避重试、死信，以及 16 KiB 有界结果保存和管理员分页查询 | 目前只接入 channel.health.changed 与 merchant.service.changed 两个固定生产者；报告事件仍未接入。结果是只读 JSON，不会创建通知 |

因此，当前已可用的功能包括部署配置表单、插件管理页静态信息卡、渠道健康与商户服务状态事件的只读处理和管理员事件结果页 GET /api/admin/plugins/events/results、用户主动选择的外部余额快照分析，以及管理员确认的监控目标启停动作。该接口只列未过期的成功投递，响应不包含原始事件 payload、event key、宿主管理的连接 URL 或凭据；结果 JSON 最多 16 KiB，并拒绝含敏感字段名的对象。PAT 调用需 admin:list_admin_plugin_event_results:execute。这是受信任插件提供的文本数据，调用方应作为文本显示，不执行或自动链接。队列不会执行插件建议或直接创建通知。报告事件尚无 producer；受控操作仅限监控目标启停，外部代理仍是合约草案，插件 UI 暂不提供业务模块自定义页面和交互。外部账号和余额读取继续由内置连接器负责。当前上传式业务入口与 Sidecar 限制以开发指南和协议参考为准。
