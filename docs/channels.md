# 渠道管理

渠道连接上游服务，凭据用于上游认证。客户端调用 AnyFlows 时使用平台 API Key，不直接使用渠道凭据，详见 [账号与访问](authentication-and-access.md)。

## 渠道与凭据

1. 在管理控制台创建渠道，选择服务适配器和模型的原生协议，按服务要求填写基础地址。
2. 添加上游凭据，通过模型发现读取目录，或手动填写完整模型 ID；需要使用其他对外名称时配置模型映射。
3. 配置模型和分组，保存后执行渠道测活，再使用 `/api` 调试页或实际客户端验证请求。

渠道 Key 调度支持「按优先级和权重」「同优先级轮询」「固定顺序，失败回退」。根据凭据容量、优先级和上游限制选择策略。模型目录和渠道测活仅验证对应请求，实际推理仍受模型能力、凭据权限、配额和服务状态限制。

对话入口和上游协议可分别配置，跨协议能力及历史回放要求见 [对话协议兼容](conversation-compatibility.md)。

## 客户端档案与诊断

客户端档案配置上游请求的客户端身份和会话策略。在「客户端档案」复制内置的标准请求、Claude Code、Codex 或 OpenCode 档案，再填写标识、名称、协议、凭据类型和身份字段。标识支持小写字母、数字、下划线和连字符，最长 64 个字符；内置档案不能直接修改。

身份请求头仅支持页面列出的字段，不接受 API Key、Cookie 或认证请求头。服务地址、认证和正文转换由适配器管理。「校验配置」仅检查配置格式，不发送推理请求。

在渠道列表点击指纹图标，打开「客户端档案配置」，选择兼容档案及修订后，点击「切换到此修订」。渠道绑定固定修订，新修订发布后需手动切换，回滚时可选择旧修订。保存时会检查凭据兼容性和请求头冲突。

旧版 Claude 身份配置发生冲突时，先关闭旧配置并保存渠道，再切换档案。停用档案后，绑定渠道在配置更新生效后拒绝新请求，已开始的请求继续执行；多节点存在配置传播延迟。

### 会话策略

默认使用客户端提供的会话标识。自定义档案可选「明确标识优先，首条消息尽力关联」：缺少标识时，根据首条用户消息生成隔离摘要。相同主体使用相同开场可能关联到同一会话，建议提供稳定标识。会话关联不提供跨账号访问权限，也不替代 Responses 的完整历史回放。

### OpenCode

创建渠道时选择 OpenCode，再按模型原生协议选择 Chat、Responses 或 Messages。服务地址内置，无需填写 Base URL。「客户端档案配置」可切换 Inference v1 和 Zen v1 入口，切换后需重新发现模型并验证调用。

凭据可选 API Key 或「公开访问」。公开访问不填写密钥，每个渠道仅允许一条公开凭据，不能与 API Key 混用；两种方式需分别建渠道。公开凭据参与并发、健康和调用统计，需使用兼容的「OpenCode（公开访问）」档案或自定义档案；原 OpenCode 档案的冻结修订仅适用于 API Key。

公开模型由上游决定，名称包含 `free` 不会自动将平台价格设为免费。公开渠道失败时直接返回错误，不会自动切换到其他渠道或收费 Key。服务器出口 IP 也可能影响公开模型的可用性。

模型要求完整工具声明时，可开启「完整工具兼容」，默认关闭。该选项补充内置工具声明，保留已有同名工具的参数和语义；网关不执行这些工具。

模型仅调用不可用的内置工具且未返回有效内容时，系统最多请求续答一次；已返回内容、混合调用真实工具或再次调用不可用工具时，请求失败。两轮共用凭据、会话、输出上限和总超时，按一次请求结算。

上游使用 SSE 时，下游可选择流式或完整 JSON。Chat、Responses 和 Gemini 保留可表达的推理文本；转为 Messages 时会协商不输出无签名思考，推理用量仍计入统计。明确要求无法转换的思考输出时会拒绝请求。

### 请求诊断

在「调试追踪」开启请求头采集后发起调用，再打开对应记录的「查看 Header」→「上游请求记录」→候选→「请求头」。这里显示档案和适配器处理后的请求，原始调用方请求位于「下游请求」。

OpenCode 可检查 `x-opencode-client` 及会话关联生成的 `x-opencode-session`、`x-opencode-session-id`、`x-opencode-project`。`User-Agent` 会实际发送，但日志固定脱敏；认证字段不显示明文。采集仅影响后续请求，历史记录无法补采。

结合上游状态码、错误正文和请求 ID 排查。请求头符合配置、目录可读取，均不代表模型推理可用。

## 代理池

在「专属代理」管理代理池，并在凭据编辑器中绑定。代理池和节点各有独立 ID，也可直接绑定单个节点。

### 导入与订阅

支持粘贴文本、上传 TXT/CSV/JSON，或填写通过 GET 获取的订阅地址。每次最多 1 MiB、256 个去重节点，导入会替换当前成员。

```text
http://user:password@192.0.2.1:3129
https://192.0.2.2:8443
socks5://192.0.2.3:1080 #备注
socks5h://[2001:db8::1]:1080
192.0.2.4:1080
192.0.2.5:1080:user:password
```

裸地址使用编辑器指定的默认协议。认证信息中的 `@`、`#` 等保留字符需百分号编码。CSV 列顺序为 `host,port[,username,password[,scheme[,remark]]]`，支持引号字段。

JSON 支持 URI 字符串数组，或包含 `host`/`ip`、`port`、`scheme`/`protocol`、`username`、`password`、`remark`/`name` 的对象数组，也支持 `proxies`、`data`、`list` 包装。混合文本会提取地址、保留备注并去重，以 `#`、`;`、`//` 开头的整行按注释处理。

订阅获取失败、返回空列表或超限列表时保留原成员。移出的节点不再参与该池选路，已有单节点绑定仍保留。订阅地址和节点密码加密保存，管理接口仅显示订阅来源主机名，编辑时留空保留原地址。

### 测活与出口选择

更新和测活间隔为 1 分钟至 24 小时，默认 15 分钟。可手动执行「测活」或「更新并测活」；手动测活不推迟订阅同步，修改节点后需重新测活。

检测通过代理发送不带上游凭据的 HTTPS GET，并校验证书；要求返回 2xx，响应体不超过 64 KiB，单次限时 5 秒，最多并行 32 个节点。检测地址可用业务站点的公开接口，例如 `https://opencode.ai/cdn-cgi/trace`。

池仅选择启用、检测通过且结果未过期的节点，按凭据 ID 稳定分配。结果有效期为配置间隔的两倍；成员或健康状态变化后可能切换。测活仅验证 HTTPS 可达性，模型和账号权限需另行验证，请求失败后不会经其他代理节点自动重放。

出口按以下顺序选择：

1. 凭据绑定的单节点或代理池。
2. 渠道绑定的代理池。
3. 全局绑定的代理池。
4. 系统网络设置中的默认出口。

绑定的池无健康节点时返回错误，不尝试低优先级出口。渠道测试、模型发现和生产请求使用相同规则。订阅获取使用系统网络设置，不经过正在更新的动态池。多节点绑定和健康状态存在约 5 秒缓存延迟。

### 删除与清理

删除池前需解除凭据、渠道和全局绑定，删除后保留节点目录及单节点绑定。列表支持批量删除，也可清理池内未通过节点或未被使用的节点；待检测、待重测节点不计入失败。

删除前预览项目并确认，每批最多 256 项。执行时重新检查引用及版本，仍被引用或正在维护的池、被其他凭据或池使用的节点会保留。订阅仍包含已清理节点时，下次同步可能重新导入。

## NVIDIA

创建渠道时，适配器选择 **NVIDIA**，原生协议选择 **OpenAI Chat Completions**。

1. 从 [NVIDIA API Catalog](https://build.nvidia.com/) 获取 API Key，保存到渠道凭据。
2. 基础地址留空时请求官方 `https://integrate.api.nvidia.com/v1/chat/completions`。自建 NIM 或网关可填写基础地址，支持带或不带 `/v1`，并保留路径前缀。
3. 通过模型发现读取 `/v1/models`，或手动填写完整模型 ID，保留命名空间。配置分组和模型映射后执行测活及实际请求。

适配器使用 Bearer 认证，支持普通、流式对话及协议转换，输出上限转换为 NIM 的 `max_tokens`。工具、推理、多模态和采样参数由模型决定。

此渠道仅支持 Chat Completions 模型，不提供原生 Responses、嵌入、图像生成或语音端点。自建 NIM 需提供兼容的 Chat Completions、模型目录和 Bearer 认证；目录读取成功后仍需确认推理权限及配额。
