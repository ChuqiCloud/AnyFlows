# 版本标签规范

AnyFlows 的公开版本使用 [Semantic Versioning 2.0.0](https://semver.org/) 命名。标签统一以 `v` 开头，版本号只使用英文半角字符。

## 标签格式

| 类型 | 格式 | 用途 |
| --- | --- | --- |
| Alpha | `v主版本.次版本.修订号-alpha.序号` | 早期预览，接口、页面和配置仍可能调整 |
| Beta | `v主版本.次版本.修订号-beta.序号` | 功能基本齐备，用于完整测试和部署验收 |
| Release Candidate | `v主版本.次版本.修订号-rc.序号` | 发布候选版本，只处理阻塞发布的问题 |
| 正式版 | `v主版本.次版本.修订号` | 可用于生产环境的稳定版本 |

示例：

```text
v0.3.0-alpha.1
v0.3.0-beta.1
v0.3.0-rc.1
v0.3.0
v0.3.1
```

预发布序号从 `1` 开始。同一阶段继续发布时递增序号，例如 `beta.2`；进入下一阶段时重新从 `1` 开始，例如 `beta.3` 之后是 `rc.1`。正式版发布后，修复只递增修订号，例如 `v0.3.1`，不再在 `v0.3.0` 后追加新的预发布后缀。

## 版本号含义

- **主版本号**：存在不兼容的 API、配置、数据库迁移或部署行为变更时递增。
- **次版本号**：增加向后兼容的功能时递增。
- **修订号**：只修复缺陷、调整文案或改进兼容性时递增。
- `0.y.z` 表示项目仍处于首个大版本之前；这一阶段的不兼容变更通过递增次版本号发布，并在发布说明中明确兼容范围。

预发布阶段按 `alpha`、`beta`、`rc` 的顺序推进。发布标签不使用 `alph`、`pre`、`preview`、`test`、日期或中文后缀，也不使用 `-final`。公开发行标签不带 `+build` 构建元数据，构建提交、来源版本和制品摘要写入发布说明及归档元数据。

标签创建后视为不可变引用。发现问题时创建新的序号或修订版本，不删除标签后复用同一个版本号。

## 三个仓库的对应关系

公共核心、企业扩展和发行仓库共享版本号，但不要求每次提交都同时发布：

1. 公共核心在 Gitea 的 `master` 完成发布合并后创建版本标签。
2. GitHub 公共仓库由导出流程生成对应内容后，使用相同的标签名称创建公开 Release。由于导出提交会重新生成 Git 历史，两个仓库的提交号不要求相同；`docs/public-core-source.json` 记录公共仓库对应的 Gitea 来源提交。
3. 企业扩展和发行仓库只有在交付企业包时才使用同名标签，并在发行清单中固定公共核心和企业扩展的完整提交号。只更新公共核心时，不为企业仓库制造空标签；只生成远程预览包时，也不占用正式版本号。测试包和正式包不得使用 `bootstrap`、分支名或短提交号作为版本标签。

创建标签之前必须先完成对应仓库的远程流水线检查。公共仓库的日常开发仍走 `main` 上的 Pull Request；代码同步 PR 合并后不会自动创建 GitHub 标签或 Release，发布时需由维护者单独创建，并上传与标签一致的归档和 SHA-256 文件。Alpha、Beta 和 RC 标记为 Pre-release，不设为 Latest；正式版才设为 Latest。

## 发布检查清单

1. 确定本次发布阶段和下一个序号，确认没有复用已有标签。
2. 更新 workspace 版本；发布企业包时，同时更新企业宿主和发行清单。所有版本字段使用不带 `v` 的 SemVer。
3. 更新 `CHANGELOG.md`，说明迁移、配置和兼容性变化。
4. 将 Gitea `develop` 合并到 `master`，确认 GitHub `main` 已包含对应发布内容，并等待远程流水线完成。
5. 在发布提交上创建附注标签，例如：

   ```bash
   git tag -a v0.3.0-rc.1 -m "AnyFlows v0.3.0-rc.1"
   git push origin v0.3.0-rc.1
   ```

6. GitHub 推送版本标签后，`Publish public release` 工作流会构建 Linux amd64 二进制和两套内置前端，生成归档与 SHA-256 文件，并发布 Release。Alpha、Beta 和 RC 自动标记为预发布，不设为 Latest。发布前核对标签指向和版本说明；发布后核对下载附件。已公开的 Release 不覆盖产物，修复时递增版本号。

标签校验由 [`tools/ci/verify-release-tag.sh`](../tools/ci/verify-release-tag.sh) 执行。它会拒绝缺少 `v`、阶段名称不在 `alpha`/`beta`/`rc` 中、序号为零或包含构建元数据的标签。
