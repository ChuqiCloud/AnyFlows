# 版本与发布

公开版本遵循 [Semantic Versioning 2.0.0](https://semver.org/)，标签以 `v` 开头：

| 阶段 | 示例 | 用途 |
| --- | --- | --- |
| Alpha | `v0.3.0-alpha.1` | 早期预览，接口和配置可能调整 |
| Beta | `v0.3.0-beta.1` | 功能测试与部署验证 |
| RC | `v0.3.0-rc.1` | 发布候选版本，处理阻塞问题 |
| 正式版 | `v0.3.0` | 稳定发行 |

预发布序号从 `1` 开始，同阶段递增；进入下一阶段重新从 `1` 开始。正式版之后递增版本号，不复用原版本的预发布序列。

兼容功能递增次版本号，缺陷修复递增修订号，不兼容变更递增主版本号。项目处于 `0.y.z` 阶段时，不兼容变更递增次版本号，并在说明中列出兼容范围。

## 社区发布

1. 更新 workspace、工作区依赖和 OpenAPI 版本，填写 `CHANGELOG.md`，说明迁移、配置及兼容性变化。版本字段不带 `v`。
2. 确认发布变更已合入 GitHub `main`，相关检查通过，版本字段与变更记录一致。
3. 在 `main` 对应提交创建附注标签，核对仓库地址、版本号和标签指向后，仅推送该标签。
4. 确认 `Publish public release` 工作流成功，发布说明与变更记录一致，归档和 SHA-256 附件齐全。

发布工作流构建 Linux、Windows、macOS 的 amd64 与 arm64 原生包，包含主程序、启动器和 Classic、Next 两套内置前端，并发布原始主程序及 SHA-256 校验文件。Linux 发行构建固定使用 Debian Bookworm，要求 glibc 2.36 或更新版本及 OpenSSL 3。Alpha、Beta 和 RC 标记为 Pre-release，正式版设为 Latest。合并 PR 不会自动创建标签或 Release。

标签和已发布产物不可覆盖；修复使用新的版本号。

首次构建因工具链或构建环境问题失败，且该版本尚未发布时，可在 GitHub `main` 修复发行工作流，再手动运行 `Publish public release`，在 `tag` 中填写原标签。工作流校验并固定该标签的源码提交，重新构建完整六平台包；版本、程序源码和变更记录均来自原标签。已发布版本不能通过此入口覆盖；程序源码变更仍需使用新版本号。

标签检查由 [`verify-release-tag.sh`](../tools/ci/verify-release-tag.sh) 执行；仅允许 `alpha`、`beta`、`rc` 预发布阶段，不接受零序号、日期后缀或构建元数据。
