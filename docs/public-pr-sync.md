# Public contribution sync

The Gitea `develop` branch remains the source of truth. A pull request merged
into the public repository's `main` branch is converted into a reviewable
pull request in Gitea; the workflow never writes directly to `develop`.

The workflow downloads the merged GitHub pull request patch rather than
reconstructing a diff from merge commits. This works for merge, squash, and
rebase merges. It creates a branch from the current Gitea `develop`, applies
the patch with three-way context, and opens a Gitea pull request.

The generated public export branches use the `sync/gitea-public-core-*` prefix
and are excluded from this workflow to prevent a synchronization loop.

The GitHub repository must define these Actions secrets:

- `GITEA_SYNC_USERNAME`: Gitea account used by the sync bot.
- `GITEA_SYNC_TOKEN`: Gitea token with permission to read the repository, push
  branches, and create pull requests.

Configure the secrets in the GitHub repository under **Settings → Secrets and
variables → Actions**. The values are not stored in this repository. The
token should belong to a dedicated service account and should be limited to
the AnyFlows repository.

If the public change set cannot be applied cleanly to `develop`, the workflow
fails without creating a branch or pull request. Resolve the change against
the current Gitea source and submit it through the normal Gitea review flow.

The generated branch is named
`sync/github-pr-<number>-<public-head-sha>`. Re-running the workflow reuses an
existing branch and does not create a second branch for the same public pull
request. `docs/public-core-source.json` is generated by the export process and
is rejected if a public pull request attempts to change it.
