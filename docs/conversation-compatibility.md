# 四协议对话兼容

对话入口覆盖 OpenAI Chat、OpenAI Responses、Anthropic Messages 和 Gemini
GenerateContent。每个入口都可以选择四种上游，形成 16 个方向；流式模式沿用同一套
请求转换规则，并由来源解码器和目标编码器处理响应。

## 请求路径

1. 受限 JSON 解析保留重复键、正文大小和结构预算检查。
2. `request_compat` 接收 SDK 的可恢复差异：可选 null、字符串数值、别名、旧式
   functions、结构化工具结果和完整 assistant 输出回放。只归一协议字段，不遍历修改
   用户 schema、工具参数或结果中的业务值。
3. 请求信封同时保存 Canonical 视图和来源上下文。同协议的原生扩展在模型映射、
   输出预算和渠道采样覆盖后仍使用受控底稿修改。
4. `ConversationConversionPlan` 完成目标归一并构造实际请求正文。路由选择、普通
   转发和候选参数覆盖共用该计划，避免预选可用而实际构造失败。
5. 可表达的 JSON schema 输出、随机种子和采样偏好映射到目标协议字段。工具历史
   按明确 ID 关联，结果按调用顺序紧邻回放。无法唯一关联的历史转为带状态的普通
   历史文本，不伪造工具执行结果。

空的停止序列按未提供处理。Gemini `VALIDATED` 工具模式在原生请求保留；跨协议
使用允许工具子集上的自动调用策略。工具结果重排保留原消息和结果块的扩展字段。
Gemini 尚未建模的内联 PDF、视频可在原生渠道保留并发送，不会因中间表示不支持而
被入口拒绝。

Chat 流式请求内部补充 usage，客户端是否可见仍由客户端偏好决定。Responses 使用
客户端完整历史回放并发送 `store:false`；私有服务器会话 ID 在持久映射尚未实现时
不能跨渠道续接。

## 响应与流

原生同协议保留供应商签名。跨协议保留推理明文和工具 ID，避免将来源签名冒充目标
供应商签名。Messages 目标使用可回放文本表达非原生推理；OpenAI 目标整理文本、
推理和工具块顺序。Messages 和 Responses 的跨协议流将交错工具事件整理为完整的
调用生命周期，保留全部参数片段和结束事件。

Responses 工具参数完成事件省略冗余工具名时，沿用已经确认的调用身份；显式冲突
的名称和参数仍按生命周期错误处理，避免关联到错误工具。
逻辑终止事件单独到达且不产生字节时，流循环仍先完成终态检查；Gemini 以 EOF
结束，不会再次读取已经释放的上游响应体。

计费使用原始 Canonical usage；客户端协议只投影其可表达的细分，总输入与总输出
保持守恒。上游没有提供可用 usage 时沿用已有估算机制。

## 能力边界

不透明的服务器状态、供应商内置执行能力以及目标协议未实现的媒体语义不能通过
补假签名、造结果或丢载荷伪装为已支持。此类内容的原生正文保留，跨协议转换明确
失败。常见可选参数、完整历史回放及工具关联差异不作为此类能力边界。

## 验证

`conversation_matrix_contract.rs` 覆盖 4 入口 × 4 上游 × 8 类历史 × JSON/SSE，
共 256 个契约组合，并补充交错推理、多文本工具结果与原样 Responses 输出回放。
`conversation-compatibility.yml` 在企业 runner 运行编译、Clippy 和相关回归。

`verify-preview-pi.yml` 校验预览产物和运行时代码一致；仅验收脚本变更时可复用已构建
产物，并分别记录二进制与验收提交。真实 Pi 连接临时 AnyFlows，
四个独立模型分别绑定一个受控协议上游。验收核对实际命中的端点、请求历史、read
工具执行、工具续答和 usage。夹具没有收费模型调用，也不修改客户端请求正文。
每次运行三轮完整矩阵，任何一轮失败都会使验收失败。受控失败抓包作为私有诊断
产物保留一天；日志只输出脱敏摘要，不包含真实业务会话。
